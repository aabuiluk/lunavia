Розділ 1 · офіційний

Що робили і що зробили на практиці

Виробнича практика організована у форматі командної розробки програмного продукту з повним циклом: планування, дизайн, frontend, backend, інтеграція, розгортання, QA та презентація. Команда працювала над продуктом Lunavia — онлайн-агентством подорожей.

Мета практики

Набути практичних навичок fullstack-розробки в умовах, наближених до реального проєкту: робота в Git із Pull Request і code review, ведення задач у Jira, спільна комунікація, проєктування API, інтеграція клієнта з сервером та публікація робочого MVP.

Організація роботи

  • команда з 8 студентів у складі загальної групи КНК-41 (2 команди × 8);
  • спільний технологічний стек: React (Vite), FastAPI, JSON/API-шар, GitHub, CI/CD, PythonAnywhere;
  • робочий процес: User Stories → гілки → Pull Request → review → merge → deploy;
  • спеціалізація за треками Design / Programming зі спільною frontend-базою для всіх.

Що мали зробити

  • пройти повний цикл delivery від планування до release;
  • побудувати React + FastAPI продукт із командною відповідальністю;
  • задеплоїти робочий MVP і показати live demo;
  • відпрацювати Git, PR, review, QA та bug reports.

Що зроблено

  • створено і опубліковано сайт туристичного агентства Lunavia;
  • реалізовано ключові сценарії користувача: маршрути, готелі, тури, підтримка, автентифікація;
  • налаштовано автоматичний деплой на PythonAnywhere;
  • закрито серію QA-багів перед фінальною демонстрацією.
Висновок розділу. Команда виконала програму практики в загальних рисах відповідно до затвердженого плану: від організаційного тижня до deployed MVP і фінальної стабілізації. Продукт доступний у мережі та демонструє повний цикл командної fullstack-розробки.
Розділ 2 · по ділу

Що реально вийшло (без зайвого пафосу)

Коротко: команда не «намалювала макет і розійшлася» — зібрала живий сайт, підключила API, виклала його в інтернет і потім тиждень гасила баги. Нижче — що саме є в продукті.

Що є на сайті зараз

Головна (Home) Hero, пошук маршруту, офери, блоки «чому ми», CTA. Контент пов’язаний із backend; є пошук міст.
Hotels Каталог готелів із фільтрами/категоріями, картками й адаптивною версткою. Є backend і правки після QA.
Tours Список турів / категорії, зв’язок із API та можливість керувати даними через admin.
Support + Tickets Сторінка підтримки, backend для тікетів / airline tickets, правки після review і QA.
Login / Register Окремі екрани входу та реєстрації: frontend + backend, потім окремий прохід по багах.
Admin + Deploy Адмінка для редагування page JSON; CI/CD через GitHub Actions на PythonAnywhere.

Що спрацювало добре

  • розподіл по сторінках дав паралельну роботу без повного хаосу;
  • шаблон «React page + FastAPI module + JSON» швидко масштабувався на нові екрани;
  • деплой на cscai.pythonanywhere.com змусив одразу ловити «у мене працює / на проді ні»;
  • Sprint 4 реально пішов у bugfix, а не в нові фічі — це правильно для release.

Де було боляче / що лишилось нерівним

  • багато merge-конфліктів на спільних CSS/Layout — типова ціна спільного frontend;
  • частина сторінок спочатку жила на mock data, інтеграція з API йшла хвилями;
  • QA виявив регресії на Hotels, auth і Support — довелося повертатися й допилювати;
  • не все з навчального «ідеального PostgreSQL CRUD всюди» вийшло однаково глибоко на кожній сторінці — десь JSON/store + admin, десь повноцінніший API.
Одним реченням. План виконали: є командний fullstack MVP у проді. Якість — робоча навчальна, із живими слідами інтеграції та bugfix, а не «глянцевий демо-макет».
